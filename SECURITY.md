# Security Policy

## Reporting a vulnerability

Please **do not** open a public issue for security problems.

Report vulnerabilities privately through GitHub:
**Security → Advisories → Report a vulnerability** on this repository
(GitHub private vulnerability reporting).

If you can't use GitHub reporting, email **security@wecrew.in** instead.

Please include:

- A description of the issue and its impact
- Steps to reproduce, or a proof of concept
- Affected versions, commits, or configuration

GitHub private reporting keeps the details private between you and the
maintainers, so prefer it for anything sensitive. We do not publish a PGP key;
if you need encrypted email, ask at the address above and we will arrange it.

## What to expect

- **Acknowledgement** within 3 business days.
- **Remediation plan** within 10 business days.
- **Fix and disclosure** coordinated with you, normally within 90 days of the
  report. We will tell you if we need longer and why.
- **Advisory**: confirmed issues are published as a GitHub Security Advisory,
  with a CVE requested where one applies. We credit reporters who want credit.

## Safe harbour

We will not pursue legal action or report you to law enforcement for research
that follows this policy in good faith. That means you:

- report the issue privately and give us reasonable time to fix it before
  disclosing it;
- access only the data you need to show the issue, and do not keep, share or
  change other people's data;
- do not degrade or disrupt our services, and do not use social engineering,
  physical attacks or spam.

If you are unsure whether something is in scope, ask us first.

## Supported versions

Only the latest commit on the default branch receives security fixes.
